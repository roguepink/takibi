# ひとくべ — 音のまとめ(2026-10-25 音のまとめ係)

ノブさんの希望: 「焚き火の音は本物の音で、リアルに。癒し系」。
音の専門家が集めた本物の録音(sound/、出どころは sound/CREDITS.md)と、アプリの音のしくみ(js/sound.js)を 1つにまとめた。

## いちばん大事な決めごと: Veo(Google Flow)の動画の音は 使わない

Veo 3.1 の動画には、はじめから焚き火の音が入っている。使えるか `tools/sound_veo.py` で 20本(山10・海9・山の熾火1)を調べた
(音は流さず、数字とスペクトルの絵で。絵は `_check/sound-ana/veo-*.png`、数字は `_check/sound-ana/veo-report.txt`)。

**よかった所**: 音楽・人の声・ハミング・「ピー」という音は どれにも入っていない(音程のある線 0%)。海の動画には 波の「ざぁ」も入っている。

**使わない理由**:
1. **パチッが とがりすぎ**。いちばん大きい所と ふだんの差が 37dB(本物の録音は 21〜23dB)。しかも 20本中 12本は 音が割れる所まで いっている(TP 0dB 以上)。
   専門家が わざわざ丸めた「パチッ」と逆で、癒しに向かない。
2. **8秒ごとに「段」ができる**。動画ごとの大きさが 7dB ばらばら(-27〜-34 LUFS)。1本の中でも はじめと終わりで 最大10dB ちがう。
   0.4秒重ねて つないでも、つなぎ目で 音が 13〜26dB 動く動画が多い(山はほぼ全部)。ランダムにつなぐと 8秒ごとに 音の調子が 変わるのが 分かってしまう。
   海の動画は 波の「ざぁ」も 8秒で切れて 別の波になる → 波のリズムが 不自然。
3. **火の動きと 音が 合っていない**。炎の明るさの変化と パチッの時刻の つながりを 調べたら 0.00(まったく関係なし)。
   「映像に合った音」に見えて、実は 合っていない。合わせるために使う意味がない。
4. しくみの都合: 動画は音なしで流す決まり(CLAUDE.md)。音を出すには iPhone で 動画の音のあつかいが ふえ、2本の重ねで 音も2重になり、電池も使う。

→ **本物の録音だけで作る**。火の音は 映像とは別に 長い輪(2〜3分)で流れるので、8秒の癖が出ない。
  ほんの少し重ねる案も考えたが、上の 1・2 は うすくしても 残る(とがったパチッは 小さくしても 目立つ)ので やめた。

## 組み合わせ(場面ごと)

| 場面 | 焚き火の音 | まわりの音 | まわりは 焚き火より |
|---|---|---|---|
| 山 | fire-1(外の焚き火・乾いた枝・パチパチ多め) | yama-1(虫とカエル・かすかな沢・遠いフクロウ) | 約 8 LU 小さい(そっと聞こえる) |
| 海 | fire-2(落ち着いたパチパチ) | umi-1(遠めの小さな波) | 約 5 LU 小さい(浜では 波が よく聞こえる) |

- 場所を変えると、焚き火の音も まわりの音も 6秒かけて 重ねて入れかえる(前は 焚き火の音は そのままだったが、場面ごとに 合う火の音を 専門家が選んでいるので 入れかえる)。
- 音の大きさの はじめの値: すべり棒「焚き火の音」80・「まわりの音」65(前は 70・50。まわりが 焚き火より 10 LU も小さく、ほとんど聞こえなかった)。
  sounds.json の gain: fire 0.8 / 山 0.65 / 海 0.82 / pops 0.9。

## パチッ(はぜる音)

下地の録音にも パチパチは入っている。その上に、ときどき 少し目立つ「パチッ」を重ねて、毎回ちがう焚き火に聞こえるようにする。
- 間: ふつう 4〜14秒、15% で 14〜26秒の長い間、10% で 0.15〜0.5秒後に もう1回(はぜが続く)。平均 約9〜10秒に1回。10分 試して 57〜70回。
  (前は 2〜9秒おき+18%で連続 → 多すぎて せわしない)
- 1回ごとに: 12個の中から(同じ音を2回続けない)、大きさ 0.4〜1倍、高さ 0.9〜1.1倍、やわらかさ(高い音を 3.5〜12kHz で しぼる = 近い・遠い)を ばらばらに。
- 左右: ±0.35(画面の火の幅くらい。前の ±0.6 は 火の外から聞こえて 不自然)。
- 大きさ: 下地のふだんの音より 3〜10dB 上(はっきり分かるが、びくっとしない)。前の 0.5 では 下地に うもれていた。

## 左右の広がり
- 焚き火は まん中(fire-1 はもともと モノラル。fire-2 は少し広がりあり)。パチッが少し左右に散る。
- まわりの音(波・虫)が 左右に広がって、火を つつむ。

## おやすみの終わり・止め方
- 最後の1分: 全体を 0.55 まで ゆっくり。
- 終わりの動画(熾火)に入るとき 0.3 → 0.12 → 0:
  0.55 より小さくすると **焚き火の音の高い所を しぼっていく**(0.3 で 約5kHz、0.12 で 約2kHz)= 熾火の「ちりちり…」の音に。
  パチッも 火が小さいほど 間が のび、鳴らない回も ふえる。
- 大きさの動きは 直線ではなく「はじめ早く だんだんゆっくり」(耳に自然。最後に すっと消える)。
- 「音を止める」: 1.5秒で 小さくして止める。止めて すぐ また鳴らしても 前の音は 自分で消えていく(前は 前の音が 残って 2重に鳴ることがあった)。
- アプリを閉じたとき(ほかのアプリ・画面を消す): 大きさを 0 にして すぐ止める。もどったら 1.5秒で ふわっと もどす(急に大きな音が出ない)。

## 古い iPhone でも重くないように
- ブラウザは 音を開いて(デコードして)持つので、長い音は メモリを使う(48kHz・1分で 左右 約23MB)。
  - fire-1 は 左右が まったく同じなので **1ch(モノラル)のファイル**にした → 72MB → 36MB、ファイルも 2.7MB → 1.9MB。
  - 場所を変えたら、前の場面の 焚き火の音・まわりの音を メモリから はなす(使っているのは いつも 2つだけ。約 90〜110MB)。
- 鳴らす部品は いつも: くり返し 2本(入れかえ中だけ 4本)+ パチッ(0.66秒・終わったら すぐ はずす)。フィルターは 2つだけ。重い計算(リバーブなど)は 使わない。
- 古い Safari(webkitAudioContext・StereoPanner なし)でも動く(左右は まん中になるだけ)。

## 音を作り直したとき
- sw.js は 音のファイルを 一度読んだら ずっと覚える。名前が同じだと 古い音のまま。
  → `sounds.json` の `"v"` を 1つ上げる(js/sound.js が `?v=` を付けて読むので、新しい方を読む)。

## 確かめ方(音は流さない)
- `tools/sound_check.py` … それぞれの音の 大きさ・つなぎ目(くり返しの切れ目)・パチッの頭とおしり。
- `tools/sound_mix.py` … アプリと同じ混ぜ方で 釣り合い(LU の差)・パチッの回数を測り、`_check/mix-yama-2min.mp3`・`_check/mix-umi-2min.mp3` を作る
  (見本は 聞きやすいように 全体を 約 -21 LUFS に上げてある。釣り合いは アプリと同じ)。
- `tools/sound_browser_check.py` … 本物の音で Chrome(音は消す)を動かし、場面の入れかえ・メモリから はなす・パチッの間・閉じる/もどる・おやすみ・止めてすぐ鳴らす を確かめる。
- `tools/sound_veo.py` … Veo の動画の音を調べる(上の表)。
- アプリ全体は `tools/ui_check.py --fake-sound`(iPhone・Android・パソコン)。

## 気になっていること
- 山の虫の録音(57秒)を くり返しているので、約52秒ごとに 似た所が来る。数分 聞くと 気づく人もいるかも。
  もっと長い 虫の録音(CC0/CC BY・日本の秋の虫なら なお良い)が見つかれば 入れかえたい。
- 本物の iPhone では まだ鳴らしていない(Playwright の WebKit は m4a を開けない。音のしくみは 無音の仮の音で確かめた)。
